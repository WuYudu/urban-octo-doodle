# 有序抓取（sequential grasping）的 QUBO 建模与求解对比

这是一个小实验：把"先抓哪个、再抓哪个"写成 QUBO，然后用四种解法在同一份代码、同一台机器上比速度和精度，四种解法是精确 MILP、贪心剥离、经典退火，以及量子退火的路径积分模拟。

结论和最初的预期不太一样。在这个规模上（30 到 360 个二值变量），精确求解器又快又准，两种退火都更慢，解也更差；一个几十微秒的贪心剥离平均只比最优差 0.8%。所以在"更快"这件事上我拿不出证据，这个仓库的价值在别处，第五节再说。

有一点要讲清楚：`sqa` 是量子退火的经典模拟（路径积分蒙特卡洛，replicas 是 Trotter 切片），跑在 CPU 上，不是量子硬件。真机要 Leap 账号和 `DWAVE_API_TOKEN`，用 `python src/solve.py --hw` 触发，我这边没有 token，所以所有数字都来自模拟。

## 问题

场景是 2D 料箱，M 个凸多边形物体随机摆放，分两类：

- `piles`：分层堆着，只能从上往下剥；
- `clutter`：随机散落，可能出现互锁。

每个物体给 3 个候选抓取，沿长轴取 −0.26、0、+0.26 三个偏置，开口方向垂直于长轴，分数由开口贴合、居中程度、指深三项加权（0.5 / 0.3 / 0.2），再乘一个该物体自己的质量系数（0.55 到 1.0，随机）。为了控制规模，实验里每个物体只用分数最高的那个候选，也就是说每个物体对应一个固定的分数，优化的是"选谁、排第几"。

阻塞关系这样定义：如果抓某个物体时，两根手指之间的通道会压到另一个物体，那另一个必须先被移走。这给出一个前置约束 o' ≺ o。如果两个物体互相挡，谁都抓不了，这种互锁在 `clutter` 里会出现。

要解的题：给一条长度不超过 T 的抓取序列，满足所有前置约束，让总分数最大。

## 编码

变量 `z[o, s]` 表示物体 o 在第 s 步被抓，s = T 这一列表示"不抓"。每个物体恰好占一个槽位，所以一共 M×(T+1) 个变量。

```
E = − Σ score(o)·z[o,s]                              目标
  + λ Σ_o (Σ_s z[o,s] − 1)²                          每个物体一个槽位
  + λ Σ_{s<T} Σ_{o<o'} z[o,s]·z[o',s]                每步最多抓一个
  + λ Σ_o Σ_{o'∈blocked(o)} Σ_q Σ_{p≥q} z[o,q]·z[o',p]   前置：o' 要排在 q 之前
```

前置项里 p 一直取到 T（包括"不抓"那一列）。这一点是整个编码的关键：如果只罚"顺序颠倒"，那么"该先移走的物体根本没被选中"这种情况一对变量都不存在，罚项是空的，于是求出来的最优解在物理上根本不可行。我第一版就是这么写的，穷举一测就露馅了，详见 `EXPLAIN_有序抓取QUBO建模.md` 第三节。

改成 p 取到 T 之后，所有罚项都是正耦合，可行解满足一个恒等式：能量等于负的总分数。这个性质很重要，它意味着罚权重只要大到足够压过分数差就行，不需要精调。

## 求解器

| 名字 | 是什么 |
|---|---|
| `milp` | pulp + HiGHS 解同一组约束，精确最优，作为参照（不经过 QUBO） |
| `greedy` | 每步抓"当前可抓且分数最高"的物体，工业上最常用的剥离策略 |
| `sa` | `dwave.samplers.SimulatedAnnealingSampler`，经典退火，跑在 CPU |
| `sqa` | `PathIntegralAnnealingSampler`，量子退火的模拟 |
| `qpu` | `dwave.system` 真机接口，需要 token，默认不跑 |

## 结果

39 个实例（堆叠族 7 个规模各 3 个种子，散乱族 6 个规模各 3 个种子），Windows、CPU、单进程：

| 求解器 | 平均差距 | 平均耗时 | 采样违约束的比例 |
|---|---|---|---|
| MILP/HiGHS | 0.00% | 48.8 ms（最慢 428 ms，360 变量） | — |
| 贪心剥离 | 0.83%（最差 6.46%） | 3 到 23 微秒 | — |
| 经典退火 SA | 2.11%（最差 9.68%） | 115 ms | 1.6% |
| 量子退火模拟 SQA | 3.99%（最差 17.91%） | 1472 ms | 4.8% |

差距是和 MILP 的最优解比，按分数算。

有三件事值得单独说。

第一，差距是随规模冒出来的。变量数在 150 以下时贪心基本不差，到 24 个物体（360 变量）才掉到 6.46%。这也说明小规模实验很容易得出"贪心就够了"的结论，而这个结论是规模不够导致的，不是问题本身的性质。

第二，那 6.46% 能定位到具体一步。24 物体那个实例里，贪心第一步抓了分数 0.822 的物体，全局解抓的是 0.534 的一个——那个物体压着三个分更高的（0.825、0.819、0.629）。全局解愿意先付这一步"开通费"把整堆打通，贪心只看当前最高分，不肯付。`figures/report_C_divergence.png` 就是这一页的对照。

第三，SQA 有接近 5% 的采样直接违反约束（one-hot 或者前置），这些样本筛掉之后它的可用性还要再打折。

## 这个实验到底说明了什么

速度上没得比，精确解在这个规模就是最优选择，这一点没什么可辩的。QUBO 的价值我觉得在两处，但都还没做完：

一是采样能一次给多个近优序列。贪心只给一条，抓空了或者物体被带倒了就得重算；退火一次能返回十几个可行的候选。这一条目前只有定性观察，没做实验。

二是能按堆分解，把每堆当成一个能塞进硬件的子问题。里德堡原子阵列的阻塞半径天然对应"挡"这个约束，这是我觉得最有意思的方向，但还没动手。

至于"量子更快"，在这个规模上没有证据，我也不打算这么说。

## 抓取位姿也是一个决策变量

前面所有实验都先在每个物体上固定一个分数最高的抓取位姿，再只优化顺序，等于假设位姿和顺序可以分开决定。真实料箱里不是这样：一个横跨两个邻居的位姿会把它们都压住；换成斜切进去的位姿，分数低一点，但可能谁也不挡。

`qubo_cand.py` 把这件事放进同一个 QUBO：变量是 `z[o, c, s]`（物体、位姿、步）。每个物体 4 个候选位姿（三个沿长轴的偏移，加一个绕法向转 32° 的斜抓），阻塞关系按位姿分开算，`cand_blocked[o][c]` 是"层级在你之上"和"抓取矩形与你重叠"两类的并集。可行解上仍然是 `E = −score`。

验证用三个小实例（4 物体、2 步、36 个变量）穷举全部状态：QUBO 最优等于暴力最优、可行解恒等式成立、不可行解能量严格更高；另外两个大实例用 MILP 参照加 400 个随机状态，全过。

结果是拥挤场景（重叠上限 0.62）5 个规模 × 3 个种子：

| | 平均分数 | 说明 |
|---|---|---|
| 只调顺序 | 4.31 | 固定每个物体的最高分位姿 |
| 位姿 + 顺序一起调 | 4.73 | 同样实例，只把位姿放开 |

15 个实例里 6 个有提升，平均 +9.8%，最大 +64.7%；93 次抓取里有 7 次选了非最高分位姿。差距最大的那组是 15 个物体：物体 5 和 14 用最高分位姿时互相压住，谁都抓不了；换成位姿 2 之后只压住物体 3，于是"先 3、再 5、再 14"就通了，抓取数从 3 个变 5 个，分数 2.16 → 3.55。

代价是变量数乘上候选数，精确解耗时变成 2–9 倍（最大那组 16 ms → 140 ms）。图在 `figures/fig5_pose_vs_order.png`。

### 再把位姿连续地磨一遍

离散的四个候选位姿定完之后，还可以在它附近做一次局部搜索：位置沿长轴挪 ±0.05、±0.10，转角 ±12°，接受条件很严格——新的位姿**不能比原来多挡任何东西**，分数还要更高。这样原来的顺序仍然可执行，不用重解。

`bench_refine.py` 把三者放在一起比（15 个拥挤实例 + 6 个纯堆叠实例）：

| | 拥挤场景 | 纯堆叠场景 |
|---|---|---|
| 固定最高分位姿 | — | — |
| 位姿+顺序联合（离散） | **+9.84%** | +0.00% |
| 联合 + 局部精修 | 再 +1.70% | 再 +0.37% |

两件事值得注意。第一，离散位姿的收益**全部**来自拥挤场景：纯堆叠时层级规则说了算，位姿怎么选都改不了遮挡关系，所以 6 个实例一个都没提升——这条边界必须写明，否则结论会被误读成普适。第二，局部精修是**均匀的小赢**：15 个拥挤实例每一个都涨了，涨幅 0.29%–2.47%，不依赖场景有多挤。它只多算了每个被抓物体九个候选，不需要再解一次 MILP。

## 还没做的事

夹爪开合和真实碰撞的几何没用，现在只按矩形重叠判断能不能抓；机械臂的移动距离和时间没写进目标函数；分数是几何代理，不是真实 CNN 输出的成功率；噪声鲁棒性没测，而这恰好是贪心最可能吃亏、全局优化可能占便宜的地方；场景是合成的，真实料箱还得先做实例分割才能自动建堆。
